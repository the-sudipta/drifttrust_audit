What gets accepted or rejected?

A proposed new version of the model. “Accepted” activates its new weights for future predictions. “Rejected” keeps the previous weights. These decisions do not block or authorize a person, network connection, or packet.

GitHub Pages serves the files. The shared model engine runs in a background worker in your browser. Uploaded measurements, session weights and records stay in this browser’s IndexedDB; they are not sent to the former hosted API. Browser-controlled evidence is inspectable, not independently trusted server evidence.

First visit? Follow these four steps
  1. Start a model session. Audit-only shows learning; gated lets checks veto model updates.
  2. Single flow: load an actual example, run inference, and compare with its known label. The model can make mistakes.
  3. Dataset replay: process 128 flows, then run the remainder. A click supplies evidence; it never forces an update.
  4. Audit evidence: expand a candidate, read its checks, verify the chain and export it. Reset to compare the other policy.

No data collection is needed for examples or replay. Your own traffic needs compatible measurements from an authorized collector; opening this page cannot capture your network.

3. Process your own measurements

Supply the 12 feature columns below. Optional label: 0 = benign, 1 = attack, blank = unknown. Labels are feedback assertions, not independently verified incidents.

Selection shows the file name and size but does not process it.

Process: validates the entire file, then scores up to 256 rows in 32-flow batches. Supplied labels can enable eligible training after prediction. An upload without labels cannot initiate training. Download: saves the header plus one real dataset row to replace with compatible measurements. Maximum file size: 2 MB.

Required columns and units
CSV column order can differ because names identify features. Use finite non-negative feature values at most 1e15. Preserve collector semantics and the same flow’s measurements. No identities, credentials or personal data are needed.

What does the model fingerprint identify?
A SHA-256 hash identifies exact weight values. A changed hash means different model content, not necessarily better behavior. The hash cannot reconstruct the weights.

Why this single-flow score?
Contribution = current attack score minus the score after replacing one transformed feature with its training-background value. Positive raises the score; negative lowers it relative to that comparison. Bars rank absolute size. Contributions need not add to the score and are not causal or SHAP effects.

Why each model version was kept or discarded
Refresh: reads this browser’s saved records without training. Verify: recomputes content hashes and links. Export: saves JSON evidence to your device. AJRs describe candidate attempts, not every prediction.
Filtering changes the display only, not past model decisions.
Chain head and evidence limits
The chain head is the latest record’s fingerprint. Each record links to the previous one. Keep a trusted head separately to help detect substitution. Someone controlling their browser can rewrite all local records and hashes. This is not immutable or externally notarized evidence and does not verify label truth.

Technical terms and current limits
This backend is a per-flow MLP, separate from the old synthetic prototype. It does not implement enterprise identity or access enforcement, calibrated security guarantees, full ADWIN, SHAP or ISO certification. GitHub Pages cannot provide a trusted multi-user server database; the optional Worker API remains a separate deployment path in the source.
